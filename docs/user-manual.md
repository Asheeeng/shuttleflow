# 用户操作手册

**项目名称**：校园摆渡车站点客流上报与AI智能动态调度系统
**版本**：v1.0
**日期**：2026-11-14

---

## 1. 系统启动

### 1.1 环境准备

1. 启动 MySQL 8.0（端口 3306）
2. 启动 Redis 6.2（端口 6379）
3. 确认数据库 `campus_shuttle` 已创建并执行初始化 SQL

### 1.2 启动后端（Spring Boot）

```bash
java -jar shuttle-backend.jar
```

- 默认端口：8080
- 启动成功标志：控制台输出 `Started ShuttleApplication in x seconds`

### 1.3 启动 AI 服务（FastAPI）

```bash
cd ai_service
uvicorn main:app --host 0.0.0.0 --port 8000
```

- 默认端口：8000
- 启动成功标志：控制台输出 `Uvicorn running on http://0.0.0.0:8000`

### 1.4 启动前端

```bash
cd frontend
npm install
npm run dev
```

- 默认端口：5173
- 浏览器访问 `http://localhost:5173`

### 1.5 访问入口

| 角色 | 入口 |
|------|------|
| 乘客端 | `http://localhost:5173/passenger` |
| 司机端 | `http://localhost:5173/driver` |
| 管理端 | `http://localhost:5173/admin` |
| 仿真台 | `http://localhost:5173/admin/simulation` |

## 2. 乘客端操作

### 2.1 扫码签到

**场景**：乘客到达站点，希望上报客流并获取排队信息。

**操作步骤**：

1. 使用手机扫描站点张贴的二维码
2. 系统自动识别站点，进入签到页面
3. 选择去向（去向 / 回向）
4. 点击「签到上报」按钮
5. 页面显示：
   - 排队序号（前方第 N 人）
   - 预计等待时长（ETA）
   - 预计来车编号

**弱网提示**：若网络异常，页面显示「正在重试…」，每 5 秒自动重试，签到数据已本地缓存不会丢失。

### 2.2 查询 ETA

**场景**：未签到也想了解等待情况。

**操作步骤**：

1. 进入乘客端首页
2. 选择站点与去向
3. 点击「查询等待时长」
4. 页面显示 ETA、预计车辆、附近车辆列表（含各车载载率）

### 2.3 取消签到

**操作步骤**：

1. 在乘客端「我的签到」页面
2. 点击「取消」按钮
3. 确认取消 → 系统从队列移除

## 3. 司机端操作

### 3.1 登录

**操作步骤**：

1. 进入司机端 `http://localhost:5173/driver`
2. 输入工号（如 D003）与密码
3. 点击「登录」
4. 系统返回司机对应的车辆与线路信息

### 3.2 设置当日运行

**操作步骤**：

1. 登录后进入「运行设置」页面
2. 确认线路（系统根据工号自动匹配）
3. 选择班次方向（去向 / 回向）
4. 点击「开始运行」
5. 车辆状态变为 `running`，开始接收心跳监测

### 3.3 到站三次点击

**说明**：司机在每站执行三类点击操作，系统据此触发事件并递推车内人数。**不要求精确计数**，仅按实际上下车人数点击。

#### 3.3.1 到站点击

1. 车辆抵达站点停稳后
2. 点击「到站」按钮
3. 系统记录 arrive 事件，显示当前站点与车内人数

#### 3.3.2 上车点击

1. 每有一位乘客上车，点击「上车 +1」一次
2. 或点击「上车」后输入本站上车总人数
3. 系统触发 board 事件，更新车内人数（守恒方程递推）
4. 若人数达到 13（满载），页面高亮提示「已满载」

#### 3.3.3 下车点击

1. 每有一位乘客下车，点击「下车 -1」一次
2. 或点击「下车」后输入本站下车总人数
3. 系统触发 alight 事件，更新车内人数

### 3.4 人数校准

**场景**：司机目测发现系统估计人数与实际偏差较大。

**操作步骤**：

1. 点击「人数校准」按钮
2. 输入目测当前车内人数
3. 点击「确认校准」
4. 系统以卡尔曼滤波融合修正，显示修正后人数

### 3.5 接单 / 拒单

**场景**：系统派发调度任务时，司机端弹出任务通知。

#### 接单

1. 任务通知弹出，显示目标站点、任务类型、ETA
2. 点击「接单」
3. 任务状态 → accepted → executing，开始导航至目标站点

#### 拒单

1. 点击「拒单」
2. 选择拒单原因（已满载 / 距离过远 / 车辆故障）
3. 任务状态 → rejected → escalated，系统转派其他车辆或转人工

### 3.6 断网缓存

- 断网时所有点击操作本地缓存（最长 2 小时）
- 页面显示「离线模式，已缓存 N 条事件」
- 网络恢复后自动批量补传，显示「已同步」

## 4. 管理端操作

### 4.1 调度大屏

**入口**：管理端首页

**页面内容**：

- 三线路全景：各站点实时客流（颜色深浅表示聚集程度）
- 各车辆实时位置与载载率（绿/黄/红三色）
- 预警事件滚动条（右侧）
- 系统状态指标（端到端时延、在线车辆数）

**操作**：

- 点击站点 → 弹出该站客流趋势图与 CUSUM 状态
- 点击车辆 → 弹出该车详情（当前任务、车内人数、历史事件）

### 4.2 调度台

**入口**：管理端「调度台」菜单

**功能**：

1. **人工观测上报**：
   - 选择站点与去向
   - 输入目测人数
   - 点击「上报」→ 系统融合入客流估计

2. **创建调度任务**：
   - 选择目标站点与任务类型（增援/调度/平衡）
   - 勾选「自动派发」
   - 点击「创建」→ 系统评分选车并派发

3. **多车分配**：
   - 勾选多个聚集站点
   - 点击「协同分配」→ 系统最小费用流计算并展示方案
   - 确认后批量派发

### 4.3 车辆管理

**入口**：管理端「车辆管理」菜单

**页面内容**：

- 12 辆车列表：车牌、线路、状态、当前载载、最后心跳
- 状态筛选：全部 / 在线 / 离线 / 满载 / 维护

**操作**：

- 点击车辆 → 查看详情与历史任务
- 可手动修改车辆状态（如标记维护）

### 4.4 预警中心

**入口**：管理端「预警中心」菜单

**页面内容**：

- 预警列表：类型（CUSUM/满载/离线/超时）、站点、消息、时间、处理状态
- 按类型与时间筛选

**操作**：

- 点击预警 → 查看详情
- 点击「处理」→ 标记已处理并记录处理方式

### 4.5 事件流水

**入口**：管理端「事件流水」菜单

**页面内容**：

- 按时间倒序展示所有事件（arrive/board/alight/checkin/observe）
- 每条事件：车辆、站点、类型、人数、时间戳

## 5. 仿真台操作

**入口**：管理端「仿真台」菜单（`/admin/simulation`）

### 5.1 消融实验

**目的**：对比 4 种调度策略效果，验证各算法组件贡献。

**操作步骤**：

1. 选择实验场景（如「早高峰」「课间」「雨雪天」）
2. 点击「运行消融实验」
3. 系统依次运行 4 策略：
   - S1：仅课表
   - S2：课表 + 卡尔曼
   - S3：课表 + 卡尔曼 + CUSUM
   - S4：全策略
4. 结果展示：
   - 对比表格（平均等待、滞留率、调度次数、满载率、空驶率）
   - 增量贡献柱状图
   - 结论文字

### 5.2 CUSUM 状态可视化

**操作步骤**：

1. 选择站点
2. 设置参数：μ₀（基线）、k（容差）、h（阈值）
3. 加载观测序列或实时接入
4. 页面展示：
   - 观测值折线
   - CUSUM 统计量 Sₜ 折线
   - 阈值线 h
   - 告警点高亮标记

### 5.3 课表预测

**操作步骤**：

1. 选择站点与时间范围
2. 点击「运行预测」
3. 页面展示：
   - 课表先验基线
   - 卡尔曼滤波预测曲线
   - 实际观测散点
   - 置信区间

### 5.4 多车分配演示

**操作步骤**：

1. 在地图上标注可用车辆位置
2. 标注需求站点（聚集站点）
3. 点击「运行分配」
4. 页面展示：
   - 最小费用流分配方案（车→站连线）
   - 各方案费用与 ETA
   - 总费用

### 5.5 卡尔曼融合演示

**操作步骤**：

1. 输入先验值 μ₀ 与初始 P
2. 设置 Q（过程噪声）、R（观测噪声）
3. 输入观测序列
4. 点击「逐步运行」
5. 页面展示：
   - 每步的预测值、观测值、卡尔曼增益 K、估计值、P
   - 估计值收敛曲线

## 6. 常见问题

| 问题 | 解决方法 |
|------|----------|
| 司机端显示「离线模式」 | 检查网络，系统会自动缓存并补传，无需手动操作 |
| 管理端大屏不刷新 | 检查 WebSocket 连接状态，刷新页面重连 |
| 满载预警未解除 | 载载率需降至 85% 以下才解除（滞回设计），等待下车点击 |
| 任务一直 pending | 可能无可用车辆，查看车辆管理页面确认车辆状态 |
| ETA 偏大 | 高峰时段 ETA × 1.3 调整，属正常行为 |
| CUSUM 频繁告警 | 可调大 k（容差）或 h（阈值）参数 |
