# 校园摆渡车站点客流上报与AI智能动态调度系统 — 答辩PPT大纲

## 第1页：封面
- 项目名称：校园摆渡车站点客流上报与AI智能动态调度系统
- 团队：8人团队（W9–W18）
- 指导老师/答辩日期

## 第2页：问题背景与痛点
- 贵州大学校内摆渡车现状：固定线路/固定站点/容量13人
- 5个核心痛点：
  1. 高峰突发客流滞后补救，缺少课表先验
  2. 多车同时到站只看到站前满载，忽略下客释放座位
  3. 站点候车人数不可观测，数据缺少置信度
  4. 司机车内人数靠人工记数
  5. 按司机而非按车辆指派，任务发出没人接

## 第3页：系统架构
- 模块化单体 + 独立AI服务（Python FastAPI）
- 六层结构：感知层→接入层→数据层→业务层→智能层→应用层
- 三闭环：秒级数据闭环 / 分钟级决策闭环 / 天周级模型闭环
- 技术栈：Spring Boot 2.7 + MyBatis-Plus + MySQL + Redis + WebSocket + Vue3 + Python FastAPI + OR-Tools

## 第4页：三个不假设原则
- 不假设乘客会扫码 → 多源融合（扫码+司机上报+摄像头）
- 不假设司机能数清 → 卡尔曼滤波融合+校准机制
- 不假设课表=客流 → 课表×转化率=潜在需求区间+CUSUM突变检测

## 第5页：多源客流上报与融合
- 事件总线：7种原子事件（checkin/cancel/arrive/alight/board/depart/calibrate）
- 卡尔曼滤波融合：K=P/(P+R)，输出带置信度的站点队列
- 满载滞回判定：≥95%持续10秒标记满载，<85%解除
- 演示：观测值10人 → 融合结果11人，K=0.886

## 第6页：短时预测与突变检测
- 课表先验：人数×转化率=潜在需求，P50/P90区间
- CUSUM突变检测：St=max{0, St-1+(xt-μ0-k)}，黄/橙/红三级预案
- 15分钟粒度定时统计快照

## 第7页：多车协同分配
- 到站拆5原子事件：到站→下客→座位释放→上客→离站
- 可用座位 = C - n⁺（下客后状态）
- 下游预留上限40%
- OR-Tools CP-SAT整数规划求解，1秒超时降级为启发式
- 消融实验：四策略对比（原始/FCFS/座位释放/座位释放+预留）

## 第8页：车辆运行与任务派发
- 评分派单：w1×(1-负载率) + w2×ETA因子 + w3×任务状态
- 反事实提示：若改派车辆X，ETA差值/负载率差值
- 失败顺延→全失败挂起并升级管理员
- 人机协同：AI只输出建议，调度员确认执行

## 第9页：前端三端+仿真台
- 乘客端：扫码签到/ETA/拥挤度
- 司机端：三步作业流程/车速锁屏/弱网降级/断网缓存补传
- 管理端：实时大屏/预警/任务/运营统计KPI
- 仿真台：消融实验/CUSUM监控/卡尔曼演示/数字孪生回放

## 第10页：运营统计与分析
- 实时KPI：总候车/车辆状态/任务完成率/预警/事件
- 线路概览：分线路候车/运行/负载率
- 站点排名：按候车人数降序
- 15分钟定时快照：等待均值/滞留/满载率/完成率

## 第11页：验证结果
- 全量测试：48项全部通过
- 3线路/21站点/12车辆/12司机/62队列
- MVP闭环：签到→融合→预警→任务→派单→执行
- AI服务集成：Java调用Python FastAPI，降级为内嵌规则

## 第12页：创新点总结
1. 三个不假设原则贯穿全系统设计
2. 卡尔曼滤波融合多源数据，输出带置信度
3. 到站拆5原子事件，OR-Tools CP-SAT最优分配
4. 反事实提示辅助调度员决策
5. 断网缓存+补传+幂等去重保障弱网可用
6. 数字孪生回放支持离线分析
