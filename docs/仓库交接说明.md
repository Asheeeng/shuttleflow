## 主要业务与算法

业务链路为乘客扫码签到/取消、司机到站及上下客、队列融合、预警、任务派发/司机处理、运营事件审计。管理台另提供车辆运行状态、课表先验、预警处置和仿真/消融入口。

当前AI主要体现为算法辅助：

| 模块 | 代码位置 | 核对说明 |
| --- | --- | --- |
| EWMA统计预测 | ai-service/predict.py | 使用指数加权历史及标准差计算P50/P90，历史不足时使用默认值 |
| CUSUM突变检测 | ai-service/cusum.py、SurgeDetectionService.java | 维护累计偏差并分级告警 |
| 卡尔曼相关融合 | ai-service/kalman.py、FusionService.java | 含增益、方差及融合相关逻辑，具体估计有效性仍需验证 |
| 多车分配 | ai-service/assign.py、MultiVehicleAssignService.java | OR-Tools CP-SAT可用时求解；否则启发式；当前默认30%下客估计、40%下游预留属于假设 |
| 课表先验 | DispatchService.java、ai-service/main.py | 人数乘转化率，推算潜在需求与预置运力 |
| Java/Python连接与降级 | AiServiceClient.java | HTTP调用与健康检查，Python不可用时使用Java内嵌逻辑 |

代码未展示LightGBM/TCN训练或大模型对话Agent编排；这些不能仅根据“AI智能体”材料标题视为已实现。仿真、算法置信度和反事实说明不等于真实校园实验结果。

## 使用方式核对

以下是按代码整理的相对路径说明，保留原README和PDF供追溯：

1. 准备Java、Maven、MySQL8；后端以Java8为编译目标。本次只在Mac的Java17上做编译核验，未做新版Windows运行验收。
2. 新库名为shuttle_db，默认连接localhost:3306。源码和release配置包含组内演示数据库口令，使用自己的本地配置时对齐连接信息；不要提交个人真实口令。
3. 初始化SQL为backend/src/main/resources/sql/init.sql或release/init.sql。**含DROP TABLE，只在明确要初始化/重置的演示库执行**，本轮没有执行。
4. 使用已有发布包：进入release目录，执行`java -jar shuttle-1.0.0.jar`，此目录的application.yml提供外置配置。
5. 从源码构建：根目录执行`mvn -f backend/pom.xml -s maven_settings.xml -DskipTests package`，再执行`java -jar backend/target/shuttle-1.0.0.jar`。构建会写target，不自动替换组内release包。
6. 页面统一在8080：`/index.html`、`/login.html`、`/passenger.html`、`/driver.html`、`/admin.html`、`/simulation.html`；不需要npm或Vite。Vue来自外部CDN，完全离线使用需要后续本地化资源。乘客可游客访问；司机/管理端登录页支持角色切换。
7. Python 服务默认仅监听`127.0.0.1:8000`，由 Java 通过内网令牌调用。Java和FastAPI进程必须设置同一个`SHUTTLE_AI_SERVICE_TOKEN`；仿真台经 Java 的受保护代理访问 AI 接口。跨主机部署应配置相同令牌并限制服务端口。Redis默认6379，作为可选组件。

## 本轮核验与边界

本轮进行了来源哈希比对、Python语法检查、发布JAR的ZIP CRC完整性检查、源/发布配置及SQL文本比对、前端两份副本比对，并另做Java编译核验。具体编译结果见[本次导入核验](import-check-2026-11-16.md)。

没有启动新系统，没有导入或重置数据库，没有运行会写业务数据的test_api.py/test_full.py，也没有复验组内测试报告的性能、消融或通过率。旧V0.2的56项后端及相关测试结果仅属于旧分支，不能用于证明这份新实现通过验收。

当前新包没有backend/src/test，未发现原报告所述完整JUnit/Vitest测试工程。后续应先复核组内报告与当前接口/数据一致性，再建立可重复的测试。

旧导入基线曾按明文密码字段查询，且没有会话/CSRF/后端角色权限保护；V1.1 已改为 Java 8 自带的 PBKDF2-HMAC-SHA256（310,000次迭代、随机盐）、会话固定防护、CSRF校验和服务端权限判定。首次启动通过幂等 `ALTER TABLE` 增加哈希列，并将现有演示口令哈希化及清空旧明文列。该改造不删除业务行、不运行初始化 SQL；新库仍应仅在空演示环境执行含 `DROP TABLE` 的初始化脚本。

### V1.1 登录与页面改造

- 产品门户：`frontend/index.html`；统一登录页：`frontend/login.html`。
- 共享新粗野主义令牌与通用组件：`frontend/neo.css`；页面会话客户端：`frontend/auth-client.js`。
- 司机接口只允许已登录且车辆与当前司机绑定的账号操作；管理接口要求管理员或调度员角色；车辆状态管理仅管理员。调度员页面只显示只读车辆管理状态。
- 游客乘客会话使用 CSRF 令牌；游客只能取消同一会话创建的候车请求。WebSocket握手也要求会话身份。
- Python AI 接口拒绝没有服务端令牌的调用；仿真界面不把令牌发送给浏览器。
- 静态部署副本位于`backend/src/main/resources/static/`，与`frontend/`页面/共享资源应保持同步。
