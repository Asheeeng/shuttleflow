# ShuttleFlow V1.3.1 正式部署验收报告

核验日期：2026-11-24，Asia/Shanghai。正式站已切换至 `5540681e68499449179e95cdb5fa5be045acb84e`。用户反馈公网业务人工测试通过。正式发布的业务源码保持该提交的内容；发布提交另外更新了文档。

## 架构与业务数据

- [正式入口](https://shuttleflow-gzu.duckdns.org) 和 [兼容入口](https://v13.shuttleflow-gzu.duckdns.org) 指向同一 Spring Boot。Nginx 使用各自 HTTPS 证书，无共享 Basic Auth。正式 Java、AI、MySQL、Redis 分别监听回环 18080、18000、3308、16379。内存实验端口 18002 只监听回环，独立于在线 AI。
- 从已冻结写入口的 V1.2 获取最终事务快照，导入新正式库，添加 V1.3 任务方向与行程关联。演练时核对 4 名乘客、1 名司机、12 辆车、3 条线路和 5 笔有效候车及五类关系；这些是演练快照数量，不是运行后的活跃用户统计。旧 V1.3 独有身份未分类，旧库完整保留，没有批量删除或混入正式数据。
- 双库旧备份与恢复演练已经验证。切换配置和最终 V1.2 快照保留在受限服务器目录，旧版库和文件没有删除。

## 维护和回滚

- 业务检查：`systemctl status shuttle-v13.target shuttle-v13-java.service shuttle-v13-ai.service`；备份与监控使用 `shuttle-v13-backup.timer`、`shuttle-v13-monitor.timer`。只按需启动/停止 `shuttle-experiment.service`，不停止正式业务。
- Navicat 保留 SSH 隧道、原密码和强制 TLS。正式库和历史库分别授予原账号 `SELECT, SHOW VIEW`；应用使用限权的独立业务账号。
- 若需要回滚，先把新入口置为维护并保存切换之后正式库的新增记录；核对处理后恢复原 Nginx、发布路径、环境配置和对应服务。旧库、新库、备份均保留，不能用旧备份覆盖新写入。现场步骤见 [单栈升级验收](V1.3单栈升级与算法实验验收.md) 和部署时保存的受保护回滚清单。若必须回到 V1.2，从停用归档恢复原来启用的服务与 cron，两个域名再次验证前不要移除新版备份。
