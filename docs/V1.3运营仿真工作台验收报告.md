验收日期为 2026-11-18。分支为 `codex/v1.3-operation-simulation`。测试使用本机独立 MySQL 库、Redis 实例、Java、FastAPI 和运营工作进程。浏览器由项目的 Playwright 1.65.1 启动，使用独立的无头 Chromium。V1.2、main 和香港 VPS 未部署本轮变更。

## 三策略同输入对照

同一大流量样本分别运行两种规则和固定班次。每组使用全自动模式、同一批 100 人、4 辆 16 座车、同一线路和采样截止时刻。脚本逐项比较三组到达时间、起点、目的地和最大等待时间，输入完全相同。

| 策略 | 上车 / 下车 | 平均候车（秒） | P95（秒） | 单向行程 | 任务创建 / 完成 |
|---|---:|---:|---:|---:|---:|
| 固定班次 | 100 / 100 | 723.5 | 918 | 21 | 0 / 0 |
| 简单阈值 | 100 / 100 | 216.0 | 416 | 18 | 3 / 3 |
| 智能调度 | 100 / 100 | 216.0 | 416 | 18 | 9 / 3 |

在这组输入中，智能策略和简单阈值的候车和服务人数相同。智能组创建数包含待人工处理的课表预置建议。课表与 Java CUSUM 使用同一模拟时钟。Python 预测、CP-SAT 和 Kalman 建议在高级实验区，未作为此组派车效果计入。候车指标只计算已上车乘客，结果属于单固定种子的本机仿真。未对全天预设逐分钟执行完整验证，也未测大规模并发。

## 车辆不足、停止和清理

另用独立库运行零车辆场景 `18053ef75cfa`。26 名虚拟乘客和 1 名真人测试乘客签到，实际触发黄、橙、红三个级别的预警。停止时档案保留 27 人尚未上车的原始状态。随后业务接口的该站候车人数降为零，真人测试乘客重新尝试取消得到业务冲突，确认该请求已被清理。原始档案为 `shortage-and-stop.json`。

启动器在 JDBC 就绪之后还验证测试管理员已经初始化，避免数据库启动与首次登录之间的竞争。两轮验收结束后，运营、Java、AI、Redis 均退出，临时凭据文件和进程记录已清理。独立测试库和只含模拟数据的验收档案保留供复核。
