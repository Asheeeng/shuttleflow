## 1. 现有实现审查

| 模块 | 原调用路径和实际效果 | 审查结论 / 本轮处理 |
|---|---|---|
| `DispatchService` | 乘客签到事件增加站点队列；同步按8/15/25阈值预警；橙/红预警调用`TaskService.createDispatchTask`。司机到站时可触发课表预置 | 阈值规则是当前自动调度主链。保留阈值业务含义；独立仿真profile提供关闭课表预置的配置项，避免课表测试任务污染场景 |
| `TaskService` | 创建自动任务后立即找车；司机接受、拒绝和完成任务 | 原车辆成本公式奖励低ETA、低载客，却用升序，实际选中最差车辆；传入的方向未持久化，也没有进入幂等键、车辆筛选和ETA。现改为明确“低成本优先”，以线路+方向+当日运行+状态过滤候选，保存任务方向、按方向计算ETA；方向缺失的旧待派任务转管理员核对 |
| `SurgeDetectionService` | 每分钟统计最近一分钟事件数并计算Java CUSUM，超阈值时建预警/任务 | 原逻辑将上客、下客、取消等所有事件都算成客流，还按滚动时间窗重复读取。现仅处理新event ID中的`checkin`，CUSUM按虚拟分钟采样窗口归一化，阈值级别只在上穿时发信号。生产定时器默认开启；仿真profile关闭墙钟定时器，由受管理员认证的仿真tick执行同一算法 |
| `FusionService` | 签到/取消走队列守恒增量；管理员观测通过AI或Java Kalman更新队列 | 原FastAPI Kalman只维护方差，未返回融合人数，Java因此把原观测值写回队列。现把数据库队列估计传给FastAPI并返回`fusedCount`，供观测业务真实更新；无AI时保留Java融合 |
| `EtaService` | 乘客ETA按所选方向累加路段时间并加60秒buffer | 原`TaskService`走不带方向的行程估算，重复站点可能选错方向。现为调度评分提供方向限定ETA；非法或不存在的路段保守回退 |
| `MultiVehicleAssignService` | `/api/admin/assign`调用Python建议或Java后备，计算估算下客和预留座位 | 该接口只生成建议、推送结果，不修改车辆、队列或调度任务。原AI读取站点全部车辆且Java后备忽略方向；现按站点/线路/方向/当日运行及可用状态过滤，拒绝无效AI响应并后备Java |
| `AiServiceClient` | 内部token和超时保护；Kalman供观测融合调用，分配服务供管理建议调用 | Python `/assign`的返回车辆集现在按线路和方向过滤。`predict`、`cusumDetect`没有Java业务调用者，不能算入当前自动派单算法 |
| FastAPI算法 | EWMA预测、CUSUM、Kalman、CP-SAT/启发式分配、课表预测、ETA | Kalman观测接口现真正参与`FusionService`队列更新；分配算法只参与管理端只读预览，CP-SAT没有驱动`TaskService`派单；预测/CUSUM/ETA/课表算法没有进入Java自动任务主链。当前Python环境未安装OR-Tools，预览使用启发式 |
| `simulation.html` | 调用消融、AI CUSUM状态、课表预测、多车建议、AI Kalman演示；WebSocket可以记录事件摘要 | 现工作台是接口演示页，不是运营仿真器：消融和多车面板不执行车辆任务，回放只播放本地摘要而不重放业务API。本轮先提供独立Python仿真器，未重做工作台 |

### TaskService评分与方向

目前成本公式为：

```text
综合成本 = 0.4 × min(1, ETA秒 / 1200)
         + 0.4 × 当前载客率
         + 0.2 × 状态成本（running=0，standby=0.5）
```

排序选择成本最低的当日可用车辆。任务方向已进入`task.direction`、幂等键、候选车辆方向过滤和ETA估算。新增测试覆盖最优车选择、反向车辆排除、同站同原因不同方向幂等键，以及无方向历史任务保护。

V1.3数据库迁移为`backend/src/main/resources/db/migration/V1.3__task_dispatch_direction.sql`。它只增加字段/索引、不重置数据；旧任务方向无法可靠还原，保持NULL，由服务升级为人工核对状态。**本轮没有把该迁移应用到V1.2或任何正式数据库。**

## 2. 独立HTTP运营仿真

仿真代码位于`simulation/`，包括固定seed客流、可暂停/继续/停止的虚拟时钟、HTTP客户端、基线模型、Java/AI隔离运行器、断言、原始数据导出和SVG图。

场景包括正常运营、下课高峰、突发客流、多车竞争/下客释放、车辆不足、司机拒单顺延。乘客使用游客会话；司机由隔离管理员API创建少量测试账号。乘客签到、司机到站/下客/上客/发车、任务接单/拒单/完成、CUSUM tick都通过HTTP接口执行。

程序会检查重复签到幂等、重复任务指派不变更车辆、方向一致、队列守恒、超容量请求以业务码409拒绝、拒单改派、车辆队列人数一致。每项模拟数据标记`source=simulated`，输出不含账号密码、Cookie、Session、CSRF或服务令牌。

实验用固定班次和简单阈值两套离散基线回放同一客流trace；两者不执行业务HTTP调用。`current_api_dispatch`才使用真实HTTP任务/司机执行结果。CP-SAT/启发式多车接口为只读建议，不计入真实派单完成率。30%下客率和40%下游预留仍属于模拟假设。

## 6. 重现方式

在V1.3 worktree运行一条验收命令即可。该脚本每次创建新的测试schema/运行目录，自动启动或刷新本机隔离环境、跑六场景、运行headless浏览器检查，并在退出时停止Java/AI/仿真Redis、清理临时凭据：

```bash
bash simulation/acceptance_local.sh
```

要单独启动服务调试时，使用`python3 simulation/runtime.py start`；重新构建并重启应用而保留当前测试库则用`python3 simulation/runtime.py refresh`；结束后`python3 simulation/runtime.py stop`。这些命令均不删除测试数据库文件。
